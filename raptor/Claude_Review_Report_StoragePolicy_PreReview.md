## I — Impact (영향 범위 및 부수효과)

### 주의 사항

1. **대시보드 응답 크기 증가**: `plan_snapshot`을 모든 프로젝트 row에 포함하면, 프로젝트 10개 기준으로 씬 5개 × 프로젝트 10개의 이미지/비디오 URL + 대본 전체가 단일 API 호출로 내려옵니다. 느린 네트워크 환경에서 대시보드 초기 로딩이 눈에 띄게 느려질 수 있습니다.
2. **기존 FIFO 삭제 범위 확장의 위험성**: `user_video_assets`의 정렬 기준(`created_at` 또는 다른 컬럼?)이 기존 `projects` FIFO 기준과 어긋날 경우 엉뚱한 에셋이 삭제될 수 있습니다.

## B — Blockage (블로커 및 리스크)

### 🔴 BLOCKER 1 — FIFO 삭제의 원자성 미보장

**현상**: `enforce_user_fifo_limit` 내에서 DB 레코드 삭제와 스토리지 파일 삭제 중 하나가 실패하면 고아 파일이 되거나 중복 삭제가 시도될 수 있음.
**권장 처리**: 최소한 `try/except`로 각 단계의 실패를 포착하고, 실패 시 에러 로그에 `project_id` + 대상 파일 경로를 기록하여 수동 복구가 가능하도록 보장해야 합니다.

### 🔴 BLOCKER 2 — 동시 프로젝트 생성 시 FIFO Race Condition

**현상**: 같은 사용자가 (혹은 탭을 두 개 열어) 거의 동시에 프로젝트를 생성하면 초과 생성이 발생.
**권장 처리**: DB 레벨의 `SELECT ... FOR UPDATE` 또는 서버 `asyncio.Lock` 사용 권장. (작성자 주: 현재 `async with db_lock:`으로 이미 방어되어 있음)

### 🟡 RISK 1 — KIE URL XSS 가능성 (낮음, 요주의)

`a href`에 직접 삽입 전 `https://` 또는 `http://`로 시작하는지 검증하는 한 줄 가드가 필요.
